# Architecture

## Layout

```
Sources/RareUI/
  Core/         pure maths and helpers with no UI in them
  Theme/        RareUITheme, the motion vocabulary, their environment keys
  Shaders/      Metal sources, compiled into the module bundle by Xcode
  Components/   the nineteen, grouped as rareui.com groups them
Tests/          the parts that can be checked exactly
Showcase/       the catalog app, generated by XcodeGen and not checked in
Tools/          Node utilities, run by hand
```

`Core` is the part worth knowing about. Nothing in it imports a component, and most of it
imports nothing but Foundation:

| File | What it is |
| --- | --- |
| `RGBA` | Colour arithmetic and the HSL conversions the code block's palette is built on |
| `CubicBezier` | A CSS easing curve, solved, for the components that drive their own clock |
| `SVGPath` | An SVG path reader, so the icons are quotations rather than transcriptions |
| `PathMorph` | Two outlines walked, sampled and lined up, standing in for flubber |
| `SpringState` | A spring integrated by hand, for when one has to be given a velocity |
| `RowCentres` | Where each row of a list is, for the things drawn beside one |
| `LiveValue` | The value an animation is passing through, as opposed to aimed at |
| `Arithmetic` | A true modulo and a clamp, matching the JavaScript rather than the Swift |

## How a component is put together

Most of them are ordinary SwiftUI: state, a body, and animations with upstream's numbers in
them. Six are not, and it is worth knowing which.

**Drawn on a clock.** `MatrixOrb`, `FluidOrb`, `GridReveal` and `NotificationBell` run a
`TimelineView` over a `Canvas` or a shader, with a small class holding the simulation
between frames. That class is never observable: it is written to from inside the draw pass,
and anything watching it would ask for another frame in response to the frame it is already
drawing.

**Solved, then drawn.** `GravityLetters` keeps a height map of the pile and tells each
glyph where it will land the moment it is dropped. `GridReveal` builds its subdivision and
schedules every split before the first frame. In both cases the frame loop only advances
what was already decided.

**Reading an animation back.** `AnimatedCounter` and `BounceSidebar` need the value an
animation is passing through, not the one it was aimed at, so that a change arriving mid
flight continues from where the thing actually is. An `Animatable` modifier writes each
frame's value into a `LiveValue` as it renders, and the event handler reads it back.

## Rules the code follows

**Nothing is allocated in a draw pass.** The canvas components run at frame rate. Geometry
is built once, keyed on the inputs that change it.

**Constants live next to what uses them, with a citation.** A spring's two numbers are
upstream's, and the comment above them says which file they came from. That is the only
thing that makes the port checkable later.

**Every public declaration carries a doc comment**, and the linter enforces it.

**Reduced motion is not optional.** Every component degrades under
`accessibilityReduceMotion`, and none of them freeze mid-animation. A component that stops
where it happens to be rather than settling is a bug.

**Views are not stored inside views.** A view held as a stored property becomes a generic
parameter, and a generic parameter spelled out of an opaque return type can be enormous.
Pass a closure, or overlay from outside.
