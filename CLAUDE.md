# Rare UI for SwiftUI: working notes

A SwiftUI port of the web library [Rare UI](https://www.rareui.com)
(MIT, (c) 2026 Swami Malode). Its twin is
[rareui-android](https://github.com/dim971/rareui-android); the two are kept
in step deliberately.

## The one rule that matters

**Motion constants come from the upstream source, not from taste.**

Every spring, easing curve, stagger delay, threshold and magic number in this
library was read out of `swamimalode07/rare-ui`'s `components/ui/*.tsx`. When
you write `interpolatingSpring(stiffness: 520, damping: 30)`, those two
numbers are upstream's, and the comment above them should say which file they
came from.

This matters because it is the only thing that makes the port checkable. Two
springs that look similar in a screen recording can feel completely different
in the hand, and there is no way to argue about it after the fact unless the
numbers are written down and traceable.

Departing from upstream is allowed, and sometimes necessary: a pointer
proximity effect means nothing on a phone, and Apple emoji do not need to be
downloaded on an Apple platform. When it happens, record it in
`docs/fidelity.md` under the component's name. Silent drift is the thing to
avoid.

The mapping between the two animation systems:

- Motion's `{stiffness, damping, mass}` is SwiftUI's
  `.interpolatingSpring(mass:stiffness:damping:)`, directly.
- Motion's newer `{duration, bounce}` is SwiftUI's `.spring(duration:bounce:)`,
  directly.
- Motion's cubic beziers are `.timingCurve(_:_:_:_:)`. Control points outside
  0...1 are fine on both sides, which matters for the overshooting curves.

## Layout

```
Sources/RareUI/
  Core/         pure maths and helpers: colour ramps, easing, solvers. No UI types.
  Theme/        RareUITheme, the motion presets, their environment keys
  Shaders/      Metal sources, compiled into Bundle.module by SwiftPM
  Components/   the nineteen components, grouped as upstream groups them
Tests/          goldens for the parts that are pure maths
Showcase/       the catalog app (project generated by XcodeGen, not checked in)
Tools/          gen-goldens.mjs: Node, run by hand
```

`docs/architecture.md` explains how a component is put together.

## Conventions worth keeping

- **Zero warnings.** Package and showcase, on the release Xcode *and* the
  current beta. Check both with `DEVELOPER_DIR`.
- **Reduced motion is not optional.** Upstream calls `useReducedMotion()` in
  nearly every component and degrades to a zero-duration transition; the
  canvas-driven ones render a single static frame. Do the same here with
  `accessibilityReduceMotion`. A component that freezes mid-animation instead
  of settling is a bug.
- **Nothing is allocated in a draw pass.** The `Canvas` components run at
  frame rate. Build the geometry once, keyed on the inputs that change it.
- **Upstream's `data-slot` becomes `accessibilityIdentifier`.** It is how the
  showcase and any UI test finds a part of a component.
- Comments explain why, not what. If a constant looks arbitrary, say where it
  came from.
- **No em dash (U+2014).** Not in code, comments, docs, commit messages
  or issue and PR text. Use a comma, a colon, a semicolon, parentheses
  or a full stop. CI fails the build if the character reappears.

## Verifying

```sh
make test                                  # goldens
make lint                                  # swiftformat --lint, swiftlint
make showcase                              # build and run in the simulator
DEVELOPER_DIR=/Applications/Xcode-<beta>.app/Contents/Developer swift build --build-tests
```

Screenshots: `xcrun simctl io booted screenshot out.png`.

A note from experience: synthetic clicks posted with `CGEvent` reach the
simulator and drive `onTapGesture`, but do **not** drive SwiftUI `Button`s.
When you need to see a pressed or presented state, prefer a pure function you
can unit-test, or temporarily force the state and screenshot it. Do not
conclude from a non-reacting `Button` that the feature is broken.

A second one: a screenshot of an animation is a screenshot of one frame, and
the frame you get is rarely the one you wanted. For anything that moves,
capture a short video with `xcrun simctl io booted recordVideo`, or drive the
component from a fixed phase you set in code.

## Staying in step with Android

A change to shared behaviour (an animation constant, a theme value, a
component's states) should land in both repositories. The Kotlin port mirrors
this structure file for file and replays the same `goldens.json`.
